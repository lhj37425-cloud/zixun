# 术语表

学过的概念都记在这里。拆解项目时，agent 会把新遇到的概念加进来。

## 工作流
步骤事先写死、每次都按同样顺序执行的流程，AI 只在其中某几步干活。适合步骤能提前写清楚的事，比如每天抓取资讯。
- 第一次出现：今日一拆的设计讨论（2026-11-13）

## agent
只给它一个目标，下一步做什么由模型自己判断。它会反复"想一步、用工具做一步、看结果"，直到把事情做完。适合步骤没法提前写清楚的事，比如拆解一个陌生项目。
- 第一次出现：今日一拆的设计讨论（2026-11-13）

## API Key
调用大模型这类在线服务时用的"钥匙"，证明是你在调用，费用也记在你的账上。只能放在本地的 .env 文件里，不能写进代码，也不能发给别人。
- 第一次出现：今日一拆的设计讨论（2026-11-13）

## RSS
网站提供的一份"更新清单"。程序定期读它，就知道网站发了哪些新文章，不用一个个打开网页去看。
- 第一次出现：今日一拆的设计讨论（2026-11-13）

## Mermaid
一种用文字画流程图的写法。在 Markdown 里写几行文字，网页就能把它画成图。
- 第一次出现：今日一拆的设计讨论（2026-11-13）

## git
记录版本的工具，像给项目拍快照：每验收通过一步就存一张，改坏了能退回去，换 agent 时也能看到每一步改了什么。
- 第一次出现：B-3.1 建 Python 项目骨架（2026-11-16）

## 静态网页
提前生成好的网页文件，浏览器直接打开就能看，不需要一直开着一个服务器。今日一拆的网页就是这样：内容有变化时重新生成一遍，平时双击 site/index.html 就行。
- 第一次出现：B-3.5 在电脑上打开网页（2026-11-16）

## 工具调用
agent 借助外部工具完成模型自己做不到的事，比如读文件、跑命令、搜索网页。模型决定用哪个工具、传什么参数，工具负责真正去做，再把结果交回给模型。
- 第一次出现：今日一拆的设计讨论（2026-11-13）

## Stitch
Google 出的 AI 界面设计工具。用一句话描述你想要的页面，它在自己的网页里生成界面图，同时产出这份界面的 HTML 代码和截图。
- 第一次出现：google-labs-code/stitch-skills（拆解）

## MCP
Model Context Protocol 的缩写，一套统一的接口约定：外部服务（比如 Stitch、浏览器、数据库）按这套约定暴露自己的功能，任何支持 MCP 的 agent 接上就能调用，不用为每个服务单独写对接代码。可以理解成「AI 世界的 USB 接口」。
- 第一次出现：google-labs-code/stitch-skills（拆解）

## Agent Skills（技能标准）
一种把「怎么干某件事」写成文件夹交给 agent 的通用写法：一个目录里有说明文件、可执行脚本、参考资料和示例。agent 判断任务相关时自动加载这份说明，照着做。好处是换 agent 不用重写，也省去每次在对话里重讲规矩。
- 第一次出现：google-labs-code/stitch-skills（拆解）

## SKILL.md
技能文件夹里的主文件，相当于这门手艺的「操作手册」：开头一小段元信息（技能名、一句话说明、允许用哪些工具），后面是步骤、必须满足的条件和反面例子。agent 读的就是这个文件。
- 第一次出现：google-labs-code/stitch-skills（拆解）

## 设计系统（DESIGN.md）
把界面的视觉规范写成一份文档：主色、字体、圆角、间距、组件长什么样。生成新页面时把这份文档一起给模型，出来的页面才像同一个产品，而不是十个风格各异的样子。
- 第一次出现：google-labs-code/stitch-skills（拆解）

## AST（抽象语法树）
把代码按语法结构解析成树状数据，程序可以在树上准确判断「这个文件里有没有一个叫 XxxProps 的类型声明」。比用文字搜索可靠，因为注释和字符串里出现同样的字不会误判。
- 第一次出现：google-labs-code/stitch-skills（拆解）

## CI（持续集成）
每次有人提交代码，服务器自动跑一遍检查（装依赖、跑测试、跑校验脚本），不通过就标红。作用是防止「本机能跑、别人一拉就坏」。GitHub 上的这套流水线叫 GitHub Actions。
- 第一次出现：google-labs-code/stitch-skills（拆解）

## Puppeteer（无头浏览器）
一个在后台偷偷开一个没有界面的 Chrome 的程序库。可以命令它打开某个网址、等页面渲染完、截图、把网页源码取下来。用来做「证明这个页面长这样」的自动检查。
- 第一次出现：google-labs-code/stitch-skills（拆解）

## node_modules
装依赖时 npm 把所有第三方代码下载到这个文件夹。它只跟当前机器有关，**不该跟着项目一起拷来拷去**，所以一般写进 `.gitignore`。
- 第一次出现：google-labs-code/stitch-skills（拆解）
