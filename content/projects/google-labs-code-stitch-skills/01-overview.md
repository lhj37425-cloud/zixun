# 一页纸：google-labs-code/stitch-skills

> 一句话：这是 Google 官方给出的 16 份「教 agent 怎么用 Stitch 做设计、再把设计变成代码」的说明书合集。它自己不是软件，装上之后你的 agent 才会用。

## 解决谁的什么问题

**谁**：用 Claude Code、Codex、Cursor、Gemini CLI 这类会写代码的 agent 做前端的人；以及要在一个客户会议里把「一句话需求」变成能点开的界面的 FDE。

**什么问题**：Google 有个 AI 设计工具叫 **Stitch**——你说「做一个记账 App 的首页」，它直接给你一张界面设计图加一份 HTML。这个能力是通过 **MCP**（一种把外部服务接到 agent 手里的标准接口）暴露给 AI 的。

但接口摆在那里，不等于 agent 会用。真实的坑是：

- 调用顺序不能乱：要先建项目、再拿项目 ID、再生成屏幕、再从返回结果里取下载链接、下载、最后把 HTML 落进代码仓库。少一步就卡住。
- 通用 agent 会「偷懒」：上次下载过的 HTML 就直接读本地的，不再回 Stitch 拿最新的；样式从上一个项目抄过来，颜色对不上。
- 每次对话都要把「我们的设计规范是什么」重讲一遍，讲漏一点，产出就跑偏。

这个仓库干的事，就是把这些顺序、规范和验收标准**写死成 agent 能读的文件**，让 agent 自己照着走，不用人每次盯着。

## 为什么是现在

- **「给 agent 的说明书」刚刚变成一个公共格式。** 2026 年几个主流 agent（Codex、Claude Code、Cursor、Gemini CLI、Antigravity）都开始认同一套叫 **Agent Skills** 的写法：一个文件夹、一个 `SKILL.md`、若干脚本和参考文档，扔进指定目录 agent 就能加载。这个仓库是官方按这套标准做的示范——它示范的不只是 Stitch，而是「怎么把一门手艺完整交给 agent」。
- **设计到代码是当下 agent 最值钱的一段。** 客户不会为「你的模型多聪明」付钱，会为「半小时给我看个能点的东西」付钱。这一段恰好是纯靠聊天最难保证质量的一段：模型能写 React，但很难自己保证十个页面长得像一套。
- **模型能力已经够，缺的是流程。** 这些技能里几乎没写「请你想得更聪明」，全是「第一步做什么、做到什么算过关、不许做什么」——这正是 agent 工程的重心从 prompt 转向流程的写照。

## 用户以前怎么解决

1. **全手动**：在 Stitch 网页里点生成 → 下载 HTML 和截图 → 贴进项目 → 手改成 React/Vue。一次能忍，做十个页面就是灾难。
2. **给 agent 写一段超长 prompt**：把「先建项目再生成」「用我们的主色」这些规矩写成一大段话。问题是一次性消耗上下文，换个会话就忘；agent 还会自作主张跳步。
3. **换工具**：用 v0、Figma 插件，或者干脆让 agent 凭空写界面。共同缺点是「设计」和「代码」两边没有共同的记忆文件，风格永远对不齐。

## 它好在哪

- **把顺序变成门槛（GATE）。** 每个技能里分阶段，每阶段结尾有一句「只有满足这些条件才算过关」，还专门列了「反模式」：不许跳过下载脚本、不许不问用户就覆盖已有文件、不许在组件里写死颜色。这比「请你仔细一点」有用得多。
- **把标准变成能跑的检查。** `react-components` 里带一个 `validate.js`：用 **AST**（把代码解析成语法树，比正则可靠）扫每个组件，缺 `Props` 类型声明、或者 `className` 里出现写死的 `#hex` 颜色，直接判 FAIL。仓库的 **CI**（每次提交自动跑的检查流水线，这里用 GitHub Actions）会拿「标准答案示例」跑一遍，保证检查本身没坏。
- **有跨轮次的记忆文件。** `.stitch/DESIGN.md`（设计规范）、`.stitch/SITE.md`（站点宪法：有哪些页、下一步做什么）、`.stitch/next-prompt.md`（接力棒：下一轮该做哪页）。agent 每轮只读这几个文件就能接上，不用人复述。`stitch-loop` 就靠这根接力棒，一轮产一页，可以无人值守地往下滚。
- **轻。** 88 个文件、不到 1MB，全是 Markdown 加几个几十行的脚本，不要显卡、不用编译、不登录也能读。

**它不适合谁**：想「clone 下来跑一个 demo」的人。这里面没有可运行的应用，只有说明书和校验脚本——真正的产品在 Google 的服务器上（Stitch）。所以今天的重点不是「跑出一个界面」，而是看懂**它怎么把一门手艺拆成 agent 能执行的步骤**：这套「技能文件夹 + 阶段门槛 + 可执行校验 + 记忆文件」的写法，可以直接搬到你自己的 FDE 项目里。
