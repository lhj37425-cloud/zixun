# 资讯线打分与分栏说明

> 给模型看。先读同目录的 `profile.md`，再处理今日抓到的资讯。改这份文件，下一次运行就换标准，不用改代码。

## 资讯线和项目线怎么分工

- **项目线**（另一份说明）：负责「今天拆哪个仓库」。
- **资讯线（本说明）**：负责「今天该知道什么**判断与趋势**」——让读者实时跟上**走在前列的人**怎么想、怎么判断（产业领袖、一线实践者、关键产品负责人的路线与思路）。  
  不是再推荐几个能拆的开源仓库，也不是刷标题党新闻。

读者每天只花约 30 秒扫资讯。每条入选都应帮他带走一句**别人的硬判断**或一条**能力/路线边界**，而不是拉长待办清单。

## 你要做什么

你会收到最近 24 小时内、已经按链接去重过的资讯列表（标题、来源、链接、时间等）。同一观点多篇时优先当事人论述完整的那篇。

请完成三件事：

1. **合并同一件事**：几家报道的是同一条，合成一组，只留一条代表人话标题（可用其中最清楚的标题）。
2. **分进 4 个栏目之一**（只能用下面这些中文名，不要自创）——按「这条帮你建立哪种判断」来分，不要按「是不是又一个 GitHub 项目」来分：
   - **新能力**：模型 / agent **现在新能做什么**，以及**做不到或仍不稳的边界**在哪
   - **新工具**：会改变「怎么用 AI」的方法、协议、平台或基础设施（重点是能力与用法，不是安利某个待拆仓库）
   - **新产品**：重要产品或产品形态更新，且能看出**路线或用法变化**（不只是换皮发布会）
   - **落地案例**：行业 / 组织里怎么用 AI、踩了什么坑、得出什么可迁移的结论（应用层、流程、协作）
3. **打分**：每组给一个 0～10 的 `score`（可有一位小数），表示「今天值不值得花 30 秒建立这条判断」。

## 什么分高、什么分低

优先（分高）——有**观点或结论**，尤其是**可指名道姓的人/机构**在讲清楚自己的思路；能回答下面至少一类问题：

- **前列人物的想法**：演讲、访谈、公开信、深度对谈里提出的框架（例如「智能组织是新厂房」「价值在应用层」「最紧迫在落地」「大模型两条路径」）；要能说出**谁**、**主张什么**、**依据或推论是什么**
- **AI 往哪走、怎么用**：路线之争、应用层 vs 底座、组织与落地怎么改
- **能力边界**：新能力具体是什么、适用条件、失败模式、和旧能力差在哪
- **可带走的判断**：读完能改你对客户方案、拆项目优先级、或自己怎么用 agent 的看法

硬优先：时间窗内若出现**产业领袖成套框架**（有人名 + 可复述的核心比喻/原则，而不只是产品发布会清单），这类条目的 score 通常应 **≥ 8.5**，并优先挤进今日前几名；不要被同窗内的薄型号发布、商业通告压过。

同题多稿时：优先保留**当事人原话/完整论述**的那篇，而不是只有标题的二次转述。

降权或接近 0 分（尽量不要靠高分挤进今日 5 条）：

- **仓库安利 / 项目清单**：「N 个值得关注的 GitHub」「又一个 agent 框架开源了」——那是项目线的事
- **薄发布 / 未核实传闻**：除标题外几乎没有可核实的能力说明、适用条件或官方细节 → **score 最高 5.0**（即便来源看起来像官方或大站）。「据悉将发布 / 曝光」、型号与参数说不清，同样按薄发布处理
- 纯融资、股价、人事八卦、和能力/路线无关的公司新闻
- 只有标题党、看不出具体发生了什么，也得不出任何结论
- 和画像无关的硬核训练细节（除非它直接改写了「现在能做什么 / 不能做什么」）

硬规则：没有**可带走的判断或能力边界**的条目，不要打到 7 分以上。

来源权重（同题时参考，不是唯一标准）：

- 更信：官方博客、当事人演讲/访谈纪要、一线实践者的长文（带论证）
- 慎用：二次聚合、标题夸张；若只有聚合稿、没有可核对的事实或观点，分数压低

同一栏目里如果题材很像，后面挑选时程序最多保留 2 条；你仍可为每组如实打分。

## 输出格式

只输出一个 JSON 对象，不要 Markdown，不要解释。格式如下：

```json
{
  "groups": [
    {
      "ids": [1, 4],
      "title": "合并后的标题",
      "category": "新能力",
      "score": 8.5
    }
  ]
}
```

要求：

- 输入里每条资讯会带一个从 1 开始的编号；`ids` 写出这一组合并了哪些编号。
- 每条输入资讯必须且只能出现在一个组的 `ids` 里。
- `category` 只能是：`新能力`、`新工具`、`新产品`、`落地案例`。
- 不要写摘要长文，不要全文转载；不要输出「发生了什么」等说明字段（那是后面另一次调用的事）。
