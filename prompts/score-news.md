# 资讯线打分与分栏说明

> 给模型看。先读同目录的 `profile.md`，再处理今日抓到的资讯。改这份文件，下一次运行就换标准，不用改代码。

## 你要做什么

你会收到最近 24 小时内、已经按链接去重过的资讯列表（标题、来源、链接、时间等）。

请完成三件事：

1. **合并同一件事**：几家报道的是同一条新闻，合成一组，只留一条代表人话标题（可用其中最清楚的标题）。
2. **分进 4 个栏目之一**（只能用下面这些中文名，不要自创）：
   - **新能力**：大模型 / agent 现在新能做什么、能解决什么问题
   - **新工具**：agent 框架、开发工具、基础设施
   - **新产品**：新上线的 AI 产品或重要产品更新
   - **落地案例**：行业里谁用 AI 解决了什么实际问题
3. **打分**：每组给一个 0～10 的 `score`（可有一位小数），表示「今天值不值得我花 30 秒扫一眼」。

## 什么分高、什么分低

优先（分高）：

- 和 agent、工具调用、产品形态、落地交付相关
- 能帮我判断「这件事能不能交给 AI / agent 做」
- 对转到 FDE 有直接参考价值

降权（分低）：

- 纯融资、股价、八卦、和 AI 应用无关的公司新闻
- 只有标题党、看不出具体发生了什么
- 和画像无关的硬核论文细节（除非它直接改变了能做什么）

同一栏目里如果题材很像，后面挑选时程序最多保留 2 条；你仍可为每组如实打分。

## 输出格式

只输出一个 JSON 对象，不要 Markdown，不要解释。格式如下：

```json
{
  "groups": [
    {
      "ids": [1, 4],
      "title": "合并后的标题",
      "category": "新能力",
      "score": 8.5
    }
  ]
}
```

要求：

- 输入里每条资讯会带一个从 1 开始的编号；`ids` 写出这一组合并了哪些编号。
- 每条输入资讯必须且只能出现在一个组的 `ids` 里。
- `category` 只能是：`新能力`、`新工具`、`新产品`、`落地案例`。
- 不要写摘要长文，不要全文转载；不要输出「发生了什么」等说明字段（那是后面另一次调用的事）。
