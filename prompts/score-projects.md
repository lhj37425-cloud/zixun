# 项目线打分说明

> 给模型看。先读同目录的 `profile.md`，再按下面的标准给候选项目打分。改这份文件，下一次运行就换标准，不用改代码。

## 你要做什么

你会收到一批候选开源项目（名字、简介、语言、来源等）。

请为**每一个**项目打两个 0～10 的分数（可以有一位小数）：

1. **relevance（值不值得拆）**
   - 和 AI、agent、大模型应用有多相关？
   - 对练习「听懂需求 → 选方案 → 搭原型」这种 FDE 思维有多大帮助？
   - 能否看清产品形态（它为谁解决什么问题），而不只是底层实现细节？

2. **beginner（零基础好不好上手）**
   - 有没有比较清楚的安装 / 使用说明？
   - 能不能在普通电脑上跑（不强制高端显卡、不强制大集群）？
   - 体量是否适合花 2～3 小时开始拆，而不是一上来就淹没在巨仓里？

分数含义（两个维度通用）：

| 分数 | 含义 |
|---|---|
| 9～10 | 非常符合，应优先考虑 |
| 7～8 | 明显有价值 |
| 5～6 | 一般，可作备选 |
| 3～4 | 勉强相关或很难上手 |
| 0～2 | 基本不符合 |

## 打分时记住

- 画像在 `profile.md`：编程基础少、靠 AI 写代码、目标是 FDE。
- 宁可推荐「小而能跑通、能讲清问题」的项目，也不要推荐「很火但完全跑不起来」的项目当主推。
- 不要因为 star 多就给高分；star 只是参考。
- 不要编造简介里没有的功能。拿不准就往低分靠一点。

## 输出格式

只输出一个 JSON 对象，不要 Markdown，不要解释。格式如下：

```json
{
  "scores": [
    {
      "repo": "作者/项目名",
      "relevance": 8.5,
      "beginner": 7.0
    }
  ]
}
```

要求：

- `scores` 里每个输入候选都要有一条，`repo` 必须和输入一致。
- 不要输出总分（程序会用两个分数计算）。
- 不要输出推荐理由（写说明是后面另一次调用的事）。
