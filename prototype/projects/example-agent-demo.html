1一页纸已完成

示例内容：这个项目是虚构的，只用来检查网页的显示效果。

解决谁的什么问题

想弄懂 agent 内部怎么运转的开发者。成熟的 agent 动辄几万行代码，新手打开仓库根本不知道从哪看起。这个项目只保留最核心的部分，几百行就能读完。

为什么是现在

大家每天都在用 agent 写代码、查资料，但很少有人知道它背后在做什么。想做 FDE，就得能跟客户讲清楚 agent 是怎么工作的、哪里可能出错。

用户以前怎么解决

要么直接读大型开源 agent 的代码，读不下去；要么只看概念文章，看完还是不知道代码长什么样。

它好在哪

  • 代码少：只有"想下一步 → 调用工具 → 看结果"这一个核心循环。
  • 能跑起来：不需要显卡，配一个模型的 API Key 就行。
  • 过程看得见：每一轮在想什么、调用了哪个工具，都会打印出来。

2流程图已完成

示例内容：这个项目是虚构的，只用来检查网页的显示效果。

用户的操作流程

flowchart TD
    A[打开终端] --> B[输入任务：帮我整理下载文件夹]
    B --> C[agent 列出计划，请你确认]
    C -->|确认| D[agent 一步步执行]
    C -->|要修改| B
    D --> E[查看结果汇报]

用户只做三件事：说任务、确认计划、看结果。中间的执行全交给 agent。

agent 内部的流程

flowchart TD
    A[收到任务] --> B[想下一步做什么]
    B --> C{需要用工具吗}
    C -->|需要| D[调用工具：读文件、跑命令]
    D --> E[看工具返回的结果]
    E --> B
    C -->|不需要，任务完成| F[写结果汇报]

关键是"想下一步 → 用工具 → 看结果"这个循环：没做完就回到"想下一步"，一直转到任务完成。这就是 agent 和工作流最大的区别。

两张图对照着看：用户看到的"agent 一步步执行"，在内部就是这个循环转了好几圈。
